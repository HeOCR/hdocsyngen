# Tables and forms: generator design (draft for eval review)

Status: design plus PR 1 (2026-11-25). Owner: tables. Review: eval, for anything that touches `hdoc_tree.v1` or `hdoc_gold.v1`.

The goal is synthetic training and selection data for the tables and forms category (decision 0032), with exact structural gold. Following the no-eval-on-synthetic rule, none of it is ever used as an evaluation set.

## Gold export for the scorer

`hdocsyngen.table_export` writes each gold table as `heocr_table.v1`, the format heocr-bench's table scorers read.
- The mapping is exact: logical columns, spans, and cell text with paragraphs joined by `\n`.
- `header_rows` is the number of leading rows made entirely of header cells.
- `pages` is filled once a producer layer gives the table's pages.

## Proposed schema additions (PR 2 and PR 5; eval reviews before any code)

- **`table.ruled`** gains `"inner"`: rulings between cells, but no outer border.
- **`table.layout`**: `{"blocks": k}` prints the logical table as `k` side-by-side copies of its columns, each with the header repeated. The gold keeps the **logical** table. The convention is draft (c) below: blocks in reading order, the right block first.
- **Section orientation**: `meta.sections[]` with `orientation: landscape` for a page range.
- **Form tree** (`hdoc_form.v1`): `form → section* → (field | table | group)`, where:
  - a `field` is `{label, value, kind: text|date|id|amount|checkbox, slot: line|box|cell}`;
  - a `group` lays its children side by side (`columns: n`).
  
  Values are fictional, generated by `values.py`. Generated IDs fail the check digit.

## Gold conventions proposed for 0032

These are drafts from the Phase 0 DEV gold, and eval has been asked to agree them:
- **(a) Side-by-side blocks** form one logical table, read in block order with the right block first.
- **(b) A matrix's diagonal labels** sit in their printed grid cell. There is no synthetic header row.
- **(c) A section label** is its own row: its text in column 0, the other cells empty.
- **(d) A margin enumerator** such as `(1)` joins the row label it precedes.
- **(e) A cross-page table** is one table. A repeated header is kept once, and `pages` is `[first, last]`.
- **(f) Footnote markers** stay in the cell text as printed.
